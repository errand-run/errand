Python API ​

Every public name is in errand.__all__. A file of work needs these:

python
from errand import entry, test, bench, track, experiment, Param, Args
from errand import has_tag, tag, out_dir
from errand import step, view
from errand import need, have, skip, Skipped

A project file needs import errand, then:

declaringconfigure, envs, Env, default_env, default_run, runners, providers, value
layersVars Venv Micromamba Conda Uv Nix Guix Module Apptainer Docker Podman Ssh Slurm Mpi Preload Windows WindowsBox Missing
runnersRunner Errand Pytest Catch2 Cargo Python Executable
serversserve, http, Server, ServeError
the command linemain

The import surface is cheap

Finding entries means importing every candidate file, so import errand loads only the standard library. Everything else is reached lazily, on first use.

Declaring work ​

Being reworked

errand's own entries are becoming a protocol any program can follow; see Writing entries.

entry ​

python
entry( name, tags = None, /, **kw ) -> Args | False

name and tags are positional-only; tags = [ … ] is accepted as a keyword too. Every other keyword is a parameter ( a Param ), or ranks: MPI processes, each running the body, overridden by --ranks ( see Several processes ). Anything else is a TypeError that says which, and where what it meant went: exclusive, cpus, ram, gpus are the command's ( -x, --cpus… ), bulk is errand.default_run.

python
if p := entry( "solve", n = Param( 1000 ), ranks = 4 ):
    ...

Returns False while the file is read to find its entries, and while another entry of the file is the one running. Returns an Args for the entry that is running.

test, track, bench, experiment ​

python
test( name, tags = None, /, **kw )
track( name, tags = None, /, **kw )
bench( name, tags = None, /, **kw )
experiment( name, tags = None, /, **kw )

entry under four names, so that the file says what the work is. They behave the same: which ones run is the target's to say, and the machine to itself is -x.

Param ​

python
Param( default, *, help = "", choices = None )

The type comes from the default: Param( 1000 ) reads its flag as an int. help shows in errand list; choices is checked before anything runs. Several values make a grid only under --grid.

Args ​

What the guard hands back:

p.<name>each declared parameter, resolved
p.out_dirPath to this run's own directory, already created
p.resultsa dict; it ends up in result.json. Numeric values are summarized above the run

Reading the environment ​

has_tag ​

python
has_tag( expr: str ) -> bool

Does the selected environment satisfy the expression? Outside errand, a file run by hand, it answers yes to everything: a file that silently disappears is worse than an import that fails loudly.

python
import sys
from errand import has_tag
if not has_tag( "driver=torch" ):
    sys.exit( 0 )
import torch

tag ​

python
tag( name: str, default = None )

The value of one tag of the selected environment, or default.

out_dir ​

python
out_dir( ) -> Path

This run's own directory, the one p.out_dir gives. Outside errand it answers ./out.

download ​

python
download( url: str, sha256: str | None = None, name: str | None = None ) -> Path

The path of the file at url, downloaded if it is not there yet, into errand-cache/downloads/<sha256>/<name> at the project root. errand-cache is a cache zone of every project: pushed when missing over there, brought back when missing here. sha256 is checked when given, never required; a URL already downloaded is found again without the network. Two runs that want one file at once download it once.

A run over Ssh that cannot reach the URL asks up the chain: the agent of the host over there downloads it into the copy, else this side downloads it and sends it. The run waits meanwhile. A run nobody follows, or a script run by hand with no route, fails and says to errand download URL here: the next push brings it. In a shell script, eval "$ERRAND_STEPS_SH" gives a download URL function that prints the path. Without errand's program, errand's Python fetches the file itself, to the same place ( the current directory stands for the project's root outside one ).

memo ​

python
@errand.memo
@errand.memo( version = 0, key = None, ignore = ( ), save = None, load = None, source = False )

The function's result, kept by its arguments in errand-cache/memo/, the project's cache zone: computed once, then read back, on this machine and on every machine the cache reaches. A result computed on lmo comes back here after the command, and goes to the next machine with its push.

The key hashes the function ( its file from the project root and its name ), version, and its arguments bound to its signature, defaults included, by what they hold: numbers, strings, containers, dataclasses, enums, numpy, jax and torch arrays ( dtype, shape, bytes ), a Path by its file's contents. Anything else is an error that says what to do: key = lambda *args, **kw: …, ignore = [ "verbose" ], or a __errand_key__() method on the class. The function's code is not part of the key: raise version when what it computes changes ( source = True adds its own source ).

Arrays, and tuples, lists or dicts of arrays, are kept as a .npz; the rest is pickled. save( value, directory ) and load( directory ) replace that. Two runs that want one result compute it once. A kept value that does not load is computed again. errand.memo.mode = "off" ( or ERRAND_MEMO=off ) computes and keeps nothing; "refresh" computes and replaces. Outside a project, the function runs and nothing is kept. f.memo_dir( *args ) says where a result is.

cache_dir ​

python
cache_dir( zone: str ) -> Path

Where a cache zone is: zone ( "/data-cache" ), a path from the project root, joined to the root, and created if missing. The root is the nearest directory above the current one that holds a project file ( errand-*.py ), so the answer is the same in a run over there and in a script run by hand here; outside a project, the current directory stands for it. Pass it down to the library that downloads or memoizes: errand sets no variable for it.

library_cache ​

python
library_cache( name: str ) -> Path

Where the library name keeps what it makes, created if missing: $ERRAND_CACHES/<name> in a run, else the user's own cache directory, else a temporary directory only the user can write in ( one another may write in is refused: what it holds may be run ). A $ERRAND_CACHES that cannot be written is said on the error output. → A library's caches

require ​

python
require( gpus = None, gpu_ram = None, ram = None, cpus = None, exclusive = False, extra = False, ranks = None ) -> list

Asks the machine for more than the run was started with, and waits until it is given ( The run asks, from its code ). Call it early, before what it protects is allocated: for Jax, before import jax. gpu_ram is what the run takes on each of its cards, a size ( "40G" ) or a share ( "75%" ); gpus without it takes cards whole. It asks for that much in all, what the run holds counting; with extra = True, for that much more than the run was started with ( by its environment and command line ), several such calls adding up ( In all, or more ). It never shrinks the claim. Once granted it sets CUDA_VISIBLE_DEVICES, HIP_VISIBLE_DEVICES and ROCR_VISIBLE_DEVICES in this process, and returns the cards. What it asked is written in the run's record. In C++: errand/require.hpp ( The run asks, from its code ).

Outside errand, with --no-queue, or in an allocation of somebody else's ( Slurm, PBS… ), it does nothing and returns [ ]. Standard library only.

What cannot be given where the run is -- more ranks than it has, what an allocation does not have, two runs that wait for each other -- stops it, and errand runs it again with what it asked up front: the process ends with 75, or, under pytest, the test is skipped.

result ​

python
result( **values )

Numbers, or words, kept in the run's record.

Saying where the run is ​

step ​

python
step( text: str = None, *, done: float = None, **values: float )

Where the run is now: text as a person reads it, done a fraction from 0 to 1, and named numbers, one curve each. Written to the run's journal, $ERRAND_STEPS, ten times per second at most; outside errand it does nothing. → Where a run is: steps

build_dir ​

python
build_dir( name: str = "main" ) -> Path

Where what the project builds goes, for this environment and this name, created if missing: in errand's caches, found again at the next run and by hand. → Build directories

view ​

python
view( path, title: str = None, content: str | bytes = None ) -> bool

path, relative to the run's directory, is a file worth watching as it evolves. With content, errand writes it atomically. Where it opens is said by errand, on the machine one looks from; outside errand, by view itself, a line on the error output. → True: the caller has nothing to say. → Where a run is: steps

Services ​

serve ​

python
serve( command, *, on = None, vars = None, cwd = None, gpus = None, gpu_ram = None, ram = None, cpus = None, exclusive = False,
       ports = None, others = False, busy = None, ready = None, idle = None, grace = None, keep = None, label = None,
       version = None, version_of = (), listen = None, always = False, hold_end = None ) -> Server

A server, by all that makes it: two requests that say the same are one server. Nothing is started, nor asked of errand, before the first url. errand's program ( errand-run ) has to be there; in a run, it is.

  • command: a list, or a string split as a shell would. {port} ( {port:NAME} of several ), in it and in vars, is the server's side.
  • on: the machine it runs on, by its ssh name, or layers: [ errand.Ssh( "lmo" ), errand.Micromamba( "jax" ) ], an errand.Env.
  • ports: { name: spec }, a spec being "ANNOUNCED:SERVER" ( either side empty ), an int ( the announced side ) or None; a bare spec is one port. others: other accounts of the machine may connect.
  • busy, ready: a line of shell ( exit 0 ), or errand.http( path, field = None, port = None ).
  • version_of: files, read where it runs, whose contents make another server; version: raised when something errand does not see changed.
  • Of its port, not of the server ( two requests that differ by these have two ports to one server ): others; listen, an address its port is listened on too ( "0.0.0.0": other machines may connect ); always, the system listens on it in errand's stead and starts errand at a connection; hold_end, each connection's end held until the server was silent that long.
  • Not of what it is: idle, grace, keep ( how long its port stays; a day ), label.

The same, from Node: lib/node ( errand-lib ), serve( [ … ], { on, vars, gpus, … } ), whose url, port, call, state, wait, stop, release return promises.

→ errand serve

Server, ServeError ​

url( path = "", port = None )where it is reached, on this machine: to be asked before each request. Answered from memory; errand is asked again at half of the lease
port( name = None )the number alone
call( fn, path = "", port = None )fn( url ); a connection that is refused asks errand again, once ( a machine that was restarted, an agent that was killed ). A server that does not start raises ServeError, with the reason
wait()started now, returned once it answers
state(), ask()how it is now; all errand answers
stop()it stops, for everybody; its port stays
release( now = False )its port is given back; now: it stops too

call knows the failures of urllib, requests, aiohttp and whatever keeps the system's own error. ServeError is also what is raised when errand refuses the request: a program that is not there, more than the machine has.

Declaring a project ​

In the project's errand-*.py files; see Configuration.

configure ​

python
errand.configure( outputs_directory = "errand-outputs", builds_directory = None, build = "build",
                  src = [ ], exclude = [ ], zones = { } )
outputs_directorywhere errand writes for the project: runs/, builds/, state/. Relative to the root, or absolute; ERRAND_OUTPUTS_DIR overrides it on one machine
builds_directorywhat errand builds, elsewhere than errand-outputs/builds/. Relative to the root, or absolute
buildwhere runners' builds go, one directory per environment: build/<env>/
srcpaths prepended to every child's PYTHONPATH
excludedirectories discovery must not walk into
zones{ path: "back" | "build" }: where a run writes in the project's copy over ssh

An unknown setting is a TypeError listing the ones that exist.

envs, Env, default_env ​

python
errand.envs[ name ] = errand.Env( stack = ( ), prepare = None, tools = None, needs = None, **tags )
errand.default_env = "name"          # optional: else the first one declared

Declares an environment; the key is its name. stack is a list of layers, outermost first: Ssh must be first, Windows and WindowsBox first or right after an Ssh. prepare, when given, is the list the preparation goes through instead, on the same machine or on another one, whose build is then carried to the run's copy. tools names what the runners start there, where the usual name is wrong ( Tools ). needs is what every run in it takes of the machine, under the command line: { "gpus": 1, "gpu_ram": "75%", "ram": "16G" }, with cpus and exclusive too ( Three ways to ask ). Keyword arguments are its tags. A name or a tag value cannot hold a comma. Only an Env can be stored.

default_run ​

python
errand.default_run = [ "tests/**::*" ]

What a bare errand run runs: targets from the project root. With none, it prints the help.

providers ​

python
errand.providers.append( declare )       # declare( root: Path ) fills errand.envs

Functions that declare environments before the project's files ( after errand-vars.py ). An installed package declares one under the entry point group errand.envs. An environment a provider declared is never the default.

runners ​

python
errand.runners.replace( runner ) -> runner
errand.runners[ "name" ] = runner
del errand.runners[ "cargo" ]

A dict, name → runner, filled with the runners errand comes with. replace puts a configured runner in place of the default one of its kind; another name adds one, which -r NAME picks. See Running a suite.
