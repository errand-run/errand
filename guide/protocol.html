What a run says, in any language ​

bash
"$ERRAND" say step "iteration 41" --done 0.41 residual=3e-7
"$ERRAND" say view convergence.html --title "Convergence"
"$ERRAND" say result seconds=1.52 primes=9592

A run tells errand where it is, what to look at, which numbers to keep, and that it needs more of the machine. None of it needs a library: it is files, environment variables, exit codes, and one command. A program that can read a variable and append a line to a file can say all of it, in Fortran as in Python.

Outside errand none of this exists, and nothing fails: a program runs the same by hand.

What a run is handed ​

variable
ERRAND_PROTOCOL1. Not set: errand does not run this program
ERRANDerrand itself, where the run is: a command to call
ERRAND_STEPSthe run's journal: a file to append lines to
ERRAND_RESULTSa file to write the run's numbers to
ERRAND_OUT_DIRthe run's own directory, when one was asked for ( -o )
ERRAND_TAGSthe tags of its environment
ERRAND_CACHESwhere a library's cache goes, by its name — Data and results
ERRAND_BUILD_DIRwhere what is built in its environment goes — Build directories
ERRAND_BUILDSwhat holds it: another name in it is another build directory
ERRAND_CLAIM_FILEits claim on the machine: what require grows

Any other ERRAND_… variable is errand's own, and may change.

What a run says ​

A step is one line of JSON appended to $ERRAND_STEPS, in one write:

json
{"t": 1795400000.12, "text": "iteration 41", "done": 0.41, "residual": 3e-07}

t is the time in seconds, text where it is, done how far, from 0 to 1. Any other key whose value is a number is a curve. → Where a run is: steps

A view is a file of the run worth looking at as it evolves, or a directory. Write it whole ( beside, then renamed: nobody sees half of it ), then name it, by its path from the run's directory:

json
{"t": 1795400001.40, "view": "convergence.html", "title": "Convergence"}

Name it again when it changed. → Every run, live

A result is a line of JSON appended to $ERRAND_RESULTS. The lines are merged, in order, under results: in the run's result.json:

json
{"seconds": 1.52, "primes": 9592}

How it ended is its exit code: 0 passed, 77 skipped, anything else failed, and the end of what it wrote on its standard error says why.

More of the machine is asked with a command, because the queue's logic lives in one place:

bash
"$ERRAND" require --gpus 1 --gpu-ram 75%      # waits; prints CUDA_VISIBLE_DEVICES=… to set

It exits with 75 when the run was stopped to be run again with its needs up front: pass that on as the run's own exit code. → Sharing a machine

Its own files go anywhere under $ERRAND_OUT_DIR. → Results and records

One command for all of it ​

errand say writes those lines for whoever would rather not:

bash
"$ERRAND" say step [TEXT] [--done X] [NAME=NUMBER ...]
"$ERRAND" say view PATH [--title TITLE] [--last FILE ...]
"$ERRAND" say result NAME=VALUE ...

In your language ​

Pythonfrom errand import step, view, require; an entry's p.results
shelleval "$ERRAND_STEPS_SH", then step, view, result, download, require
C++#include <errand/say.hpp> ( errand::step, view, result, out_dir ) and <errand/require.hpp>; header-only, C++17; -I{errand_include} in a runner's build line
anything elsethe lines above, or "$ERRAND" say …
cpp
#include <errand/say.hpp>

errand::step( "iteration 41", 0.41, { { "residual", 3e-7 } } );
errand::view( "convergence.html", "Convergence" );
errand::result( "seconds", 1.52 );

A binding does nothing more than this: read the variables, append the lines, run "$ERRAND" require. One test holds them all to it: the same small program in each language, and what its run left.

The design: ADR 0032.
